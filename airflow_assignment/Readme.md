# Project: The Zombie Apocalypse Survival DAG
### System Designation: Automated Mid-Night Zombie Defense & Combat Protocol

## Overview & Design Rationale
When bunker power drops and survivors face extreme physical exhaustion, human error during night shifts becomes fatal. This project replaces a dangerous, manual eight-step defensive checklist with an automated, reliable Apache Airflow data pipeline. 

The pipeline runs entirely on a strictly timed schedule during peak zombie activity. It manages everything chronologically: scanning enemy proximity, deploying tactical decoys, measuring structural stress on the compound walls, locking down internal safe rooms, and executing high-explosive defense grids only when a breach is imminent.

---

## Operational Pipeline Flow (8 Total Tasks)

The workflow consists of exactly eight tasks arranged in a linear-to-branching topology:

1. **`scan_horde_proximity` (PythonOperator)**: Scans external thermal and seismic sensors to establish an initial count of active zombies surrounding the bunker.
2. **`check_decoy_flares` (BashOperator)**: Fires high-decibel sonic distraction canisters 500 meters North of the base to draw immediate roaming threats away from the primary structures.
3. **`measure_wall_integrity` (PythonOperator)**: Analyzes real-time pressure and impact data on physical barriers to calculate an automated percentage breach risk score.
4. **`seal_inner_bunkers` (BashOperator)**: Pre-emptively engages secondary internal hydraulic panic door deadbolts to guarantee fallback security.
5. **`analyze_combat_necessity` (BranchPythonOperator)**: Serves as the primary decision engine. It evaluates the structural risk score to route execution paths dynamically.
6. **`activate_claymore_mines` (BashOperator)**: *[Branch Path A]* Detonates explosive perimeter claymore grids. Runs **only** if structural breach risk is high (≥ 70%).
7. **`hold_ammunition_reserves` (BashOperator)**: *[Branch Path B]* Keeps defensive arrays offline to preserve limited munitions. Runs **only** if breach risk is low (< 70%).
8. **`assess_horde_casualities` (PythonOperator)**: A converging task that aggregates historical run metrics to compile a final tactical kill report for the night shift.

## Advanced Airflow Architecture Features

### 1. Multi-Stage XCom Inter-Task Communication
To ensure tasks do not operate blindly in silos, data is dynamically passed between components using Airflow XCom variables:
* **`perimeter_threat_score`**: Generated by `scan_horde_proximity` and pulled by `assess_horde_casualities` at the end of the pipeline to measure combat performance metrics against the initial swarm numbers.
* **`wall_breach_risk_score`**: Generated by `measure_wall_integrity` and pulled by `analyze_combat_necessity` to make the logical choice between firing weapons or standing down.

### 2. Conditional Branching & Task Skipping
To protect precious resources, a definitive conditional skip mechanism is embedded via `BranchPythonOperator`. If the calculated wall breach risk does not meet or exceed the critical threshold of **70%**, the pipeline safely bypasses `activate_claymore_mines` to conserve explosives. Airflow explicitly marks this skipped path as pink/salmon in the graph view, satisfying all safety and assignment parameters.

### 3. Chronological Cron Schedule (`15 3 * * *`)
Instead of a generic daily flag, the DAG is scheduled using the cron string `15 3 * * *` to trigger every single morning at exactly **03:15 AM**. This timestamp marks the point of deepest night when human guard exhaustion is highest and zombie horde activity levels peak, ensuring automation runs when it is most critically needed.

### 4. Enterprise-Grade Structured Logging
Every Python task drops standard print statements entirely, instead calling Airflow’s system logger (`logging.getLogger("airflow.task")`). Logs systematically track and classify details across multiple strict layers from standard `info` checkpoints to `warning` blocks for skipped tasks and `critical` statuses during intense horde pressures.

## API Triggering Verification (Swagger UI)

To bypass the web interface and save laptop battery levels, the workflow is launched directly via the built-in **Airflow Swagger API Interface** (`http://localhost:8080/api/v1/ui/`).

* **Endpoint**: `POST /dags/zombie_survival_protocol/dagRuns`
* **Path Parameter (`dag_id`)**: `zombie_survival_protocol`
* **Configured Request Body Payload**:
